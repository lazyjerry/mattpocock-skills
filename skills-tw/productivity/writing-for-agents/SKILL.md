給任何 agent 讀取的文件的參考指南：一份 skill、一份 `AGENTS.md` / `CLAUDE.md`、一份透過指標到達的文件。包裝方式不同，但撰寫原則相同：同樣的槓桿讓每一份文件都變得可預測，因為 agent 每次執行的是同一個 _流程_，而不是產出同一個結果。

當你撰寫的文件是一個 skill 時，請閱讀 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md) 以了解 frontmatter、呼叫方式的選擇，以及 router skill。

## 情境指標（Context pointers）

**情境指標（context pointer）** 是保存在 agent 情境中的一個參考，它指名某個位於情境之外的素材，並編碼抵達該素材的條件。skill 的 description 就是一個例子；`AGENTS.md` 中指名某份文件的一行也是同一種東西。指標的 _措辭_，而非其目標本身，決定了 agent 何時抵達該素材，以及抵達的可靠程度。一個必要的目標若躲在措辭薄弱的指標背後，就是一個變異性錯誤：先把措辭磨利，只有在磨利失敗時才把素材內嵌進來。

一個指標要做兩件事：說明素材是什麼，並列出應觸發抵達該素材的**分支（branches）**（分支是文件所處理的一個不同案例，因此不同的執行會走過它的不同路徑）。常駐載入的指標中，每一個字在每一輪都要付出代價，所以它比正文更需要嚴格削減：

- **把觸發詞放在最前面**：指標就是它發揮觸發作用的地方。
- **一個分支對應一個觸發詞。** 只是把同一個分支換個說法的同義詞，其實是同一個分支寫了兩次；把它們合併，只保留真正不同的分支。
- **刪掉正文已經涵蓋的身份說明。**

## 兩種負載

你新增的每一份文件與每一個指標，都會花費兩種預算之一：

- **情境負載（Context load）** 是常駐載入素材加諸在 agent 情境視窗上的成本：`AGENTS.md` 的一行、skill 的 description、任何每一輪都待在情境中的東西，無論它有沒有被觸發，都要花費 token 與注意力。
- **認知負載（Cognitive load）** 是加諸在人類身上的成本：有哪些文件存在、什麼時候該去查哪一份。人類就是索引。這不是要盡量壓低的成本：它是人類自主判斷所付出的代價；把它花在人類判斷真正重要的地方，在不重要的地方把它移除。

只透過指標才能抵達的素材，能以指標本身那一行的代價逃過情境負載；完全沒有指標的素材，則完全仰賴認知負載。

## 資訊層級

一份文件由兩種內容類型構成：**步驟（steps）**（agent 執行的有序動作）與**參考資料（reference）**（依需求查閱的定義、規則、事實）。這兩者可以自由混合：全部是步驟（一份食譜）、全部是參考資料（一份審查的規則、本 skill）、或兩者兼具。核心決策在於每一項內容應放在**資訊層級（information hierarchy）**的哪個位置，這是一個依 agent 需要該素材的迫切程度排序的階梯：

1. **檔內步驟（In-file step）** 是主要層級：agent 依序執行的動作。
2. **檔內參考資料（In-file reference）** 是依需求查閱的內容。通常是一組合理攤平的同級項目（一份審查的每條規則都在同一階），這是一種合宜的安排，不是壞味道。
3. **外部揭露的參考資料（Disclosed reference）** 被推到獨立檔案中，透過情境指標抵達，只有在指標被觸發時才載入。範圍從同一資料夾中的同層檔案，一路到可存在任何位置、任何文件都能指向的完全外部參考資料。

推得太少，頂層會膨脹；推得太多，就會把 agent 實際需要的素材藏起來。這種張力就是整個決策的核心。

**漸進式揭露（Progressive disclosure）** 是沿著階梯往下移的動作（移出主檔案、藏到指標之後），目的是讓頂層保持清晰易讀。這主要不是 token 上的最佳化：而是保護層級結構的手段。分支是最乾淨的揭露測試：把每個分支都需要的內容內嵌，把只有部分分支才會用到的內容推到指標之後。當一份文件含有步驟時，本該被揭露卻留在檔內的參考資料會掩埋這些步驟，讓是否留意到它們變成擲硬幣式的機率問題：這不只是易讀性上的槓桿，更是變異性上的槓桿。

**共置（Co-location）** 是階梯之內的搭配動作：階梯決定一項內容 _往下放多深_，共置則決定它一旦落到那個位置後 _身邊放了什麼_。把一個概念的定義、規則和注意事項放在同一個標題底下，而不是分散各處，這樣讀到其中一部分時，其相鄰內容也會一併出現。判斷標準：這份文件讀起來應該像是專為 agent 撰寫的說明文件。分組整理的素材讀起來就是這樣；分散的素材則不然。（這與重複不同：重複是把同一個意思講兩次；分散則是把一個意思拆散在許多地方。）

**蔓生（Sprawl）** 是這裡的失敗模式：一份文件單純太長，即使每一行都是活的、獨一無二的。注意力會隨著份量過多而變薄，多出來的每一行都是需要額外留意其相關性的一行。解法就是階梯：把參考資料揭露到指標之後，並依分支或順序拆分文件，讓每條路徑只攜帶它需要的部分。

## 步驟與完成標準

每一個步驟都以一個**完成標準（completion criterion）** 收尾，也就是告訴 agent 這項工作已經完成的條件。有兩個特性讓它成為一個槓桿：

- **明確性（Clarity）**：agent 能不能分辨完成與未完成？一個模糊的界線（「已達成理解」）會招致**過早完成（premature completion）**：在真正完成之前就結束這個步驟，注意力滑向了 _已完成_ 這件事本身，而不是完成的內容。眼前可見、還沒做的步驟（**完成後步驟，post-completion steps**）提供了拉力；完成標準的明確性則是抵抗力。優先順序是：**先把界線磨利**（這是局部且成本低的做法）；只有在界線確實無法化簡 _且_ 你觀察到搶進度的現象時，才把後面的步驟藏起來，把序列拆開。藏起來這一招只有跨越真正的情境邊界時才有效（一次交接或一次 subagent 派工；同一情境內呼叫仍會讓後面的步驟留在情境中，起不了作用）。
- **要求程度（Demand）**：它要求了多少。「每一個被修改的 model 都要交代清楚」會迫使工作做得徹底，而「產出一份變更清單」則不會。要求程度驅動**功夫（legwork）**（agent 在工作中投入的挖掘，隱含在措辭裡，而不是寫成獨立的一個步驟），而且它不僅限於步驟：「每一條規則都套用」約束的是一整批攤平的參考資料，就跟「每一個步驟都完成」約束一段序列一樣，這正是為什麼一份全是參考資料的文件依然能帶有窮盡式的門檻。

最強的標準，既可檢驗，又窮盡無遺。

## 何時該拆分

把一份文件拆成兩份，會花費兩種負載之一，所以只有在這個切分值得時才拆：

- **按順序拆分**：在一段步驟序列中，若完成後步驟誘使 agent 對眼前這一步敷衍了事，就在那裡拆分。讓它們暫時不在視野內，能對目前的任務逼出更多功夫。反過來要小心：把幾段序列合併，會讓每個步驟的後續步驟暴露在其後續內容之前，招致過早完成。
- **按呼叫方式拆分**，這是 skill 特有的做法：見 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## 觸發詞（Leading words）

**觸發詞（leading word）** 是一個已經存在於模型預訓練知識中的精簡概念，agent 在執行文件時會用它來思考（_lesson_、_fog of war_、_tracer bullets_）。作為一個 token 反覆出現，而不是作為一句話，它會累積出一個分散式的定義，並以最少的 token 錨定一整個行為區域，方法是喚起模型已經具備的先驗知識。自創詞彙如果定義清楚也是可行的，但一個自創詞彙喚不起任何先驗知識：你得用定義的 token 來支付一個既有詞彙本來免費提供的東西；優先選用既有詞彙。

它有兩次錨定作用。在正文中，是 _執行_：每當這個詞出現，agent 都會做出同樣的行為反應；在攤平的參考資料中，它能把注意力聚焦在該去找哪一類東西上。在指標中，是 _呼叫_：當同一個詞同時出現在你的 prompt、你的文件與你的程式碼庫中，agent 就能把那個共通的用語與素材連結起來，更可靠地抵達那裡。

主動尋找可以用觸發詞重構的機會。一個三元組在三個地方各講一次、一個指標花一整句話才點出一個概念。每一個都是等著被收斂成單一 token 的段落：

- 「快速、確定性、低額外負擔（fast, deterministic, low-overhead）」→ _tight_（一個 _tight_ 迴圈）。
- 「一個你信得過的迴圈（a loop you believe in）」→ _red_，把一個模糊的關卡變成一個二元可觀察的狀態（迴圈在這個 bug 上變 _red_，不然就沒有）。

你會贏兩次：token 更少，而且給 agent 一個更鮮明的掛鉤來安放它的思考。假設每一份文件都帶著觸發詞可以取代的重複敘述。去把它們找出來。

**否定敘述（Negation）** 是這個槓桿旁邊的失敗模式：用禁令來引導，反而會把被禁止的行為拉進情境裡，讓它變得 _更_ 顯眼，而不是更不顯眼。_別去想一頭大象_，結果滿腦子都是大象；否定詞只是個弱修飾語，會被強烈啟動的概念蓋過去，所以這個禁令有一半讀起來反而像是在指示去做那件事。要用**正面表述**去下指令：直接陳述目標行為（「寫一行式的註解」），這樣被禁止的行為就根本不會被提起。禁令只有在作為一個無法用正面方式表述的硬性防護欄時才值得存在；即便如此，也要搭配正面目標，讓注意力落在該做什麼上。

## 削減

- 讓每個意思只有**單一事實來源（single source of truth）**：只有一個權威的地方，這樣要改變行為時只需要改一處。**重複（Duplication）**（同一個意思出現在不只一個地方）會付出維護成本與 token 成本，還會把一個意思在階梯上的顯著程度膨脹到超出它應有的等級。（這是觸發詞的意外反面：觸發詞是刻意重複一個 token，但絕不重複意思本身。）
- **環境（environment）** 本身也是一種事實來源（`package.json` 的 scripts、設定檔、目錄結構、`--help` 的輸出），而一份重述環境內容的文件就是一份**快取（cache）**：一份查詢結果的副本，只有在查詢成本高昂時，載入它才值得。要快取的是 agent 靠查看找不到的東西：沒寫下來的慣例、某個選擇背後的理由、任何設定檔都不會坦白的陷阱。單一檔案、單一指令就能查到的東西，就交給環境去保管，那裡才不會過時。
- 檢查每一行的**相關性（relevance）**：它是否仍然關乎這份文件的作用？一行內容會因為從未關乎任務（純粹的鋪陳說明，或是本該被揭露出去的分支）或因為它描述的行為或世界已經改變而過時，從而失去相關性。較短的文件比較容易維持相關性。若沒有削減的紀律，預設的結局就是**沉積物（sediment）**：陳舊的層層堆積，因為新增感覺安全、移除感覺有風險，於是不斷累積，直到你必須鑽透這些層層堆積，才能找到還活著的內容。
- 逐句獵捕**空指令（no-ops）**：一條模型預設就會遵守的指示，寫出來等於白白付出負載卻什麼都沒改變。判斷標準（它是否改變了行為，相對於預設情況而言？）是相對於模型而定，不是相對於讀者而定：兩個人對某句話是不是空指令有分歧，其實是他們對「預設情況」的認知有分歧，要靠實際執行這份文件來裁定，而不是靠辯論。當一句話沒通過測試時，就整句刪掉，而不是刪減字句。這個測試同樣適用於觸發詞：一個弱到贏不過預設情況的詞（在 agent 本來就已經算徹底時還說「要徹底」）就是空指令，修法是換成更強的詞（_relentless_），而不是換一種技巧。
