# Wizard

**wizard（精靈）** 是一個 bash 腳本，會一步步帶領人類完成一個手動流程，這種流程如果自己做會很繁瑣，每次都要重新跟 AI 解釋也很麻煩。它會開啟每個網址，明確說明要點什麼、複製什麼，擷取數值，把它們寫到該去的地方（`.env`、GitHub secrets），在每個階段都做確認，並顯示還剩多少階段。它可能會設定第三方服務、執行一次性遷移，或是把專案從一個狀態搬到另一個狀態。

令人愉快的使用者體驗已經由 [template.sh](template.sh) 解決了：逐階段進度、確認關卡、跨平台網址開啟（包含 WSL）、隱藏式密鑰輸入、冪等的 `.env` upsert、`gh secret`/`gh variable` 寫入，以及結尾摘要。**你的工作只是界定流程範圍並撰寫各個階段。** 上面標示 `STAGES` 之前的程式庫在每個精靈中都是一樣的；這種一致性正是重點：絕不要手動去修改它。

精靈預設是暫時性的：為了單次執行而建立，存放在暫存或 `scripts/` 路徑，工作完成後就刪除。只有在使用者想要一個可重複使用、應該留在儲存庫中的設定路徑時，才提交它。

## 流程

### 1. 界定流程範圍

找出人類必須執行的每一個手動步驟，以及過程中要擷取的每一個數值。先讀過儲存庫，不要憑空亂問：

- 對於設定作業：`.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、框架設定，以及 `.github/workflows/*`（每一個 `secrets.*` / `vars.*` 參照都是精靈必須產生的一個數值）。
- 對於遷移或轉換作業：目前的狀態、目標狀態，以及兩者之間不可逆的動作。

然後把有順序的階段清單，以及每個階段會產生的數值，展示給使用者看，並加以確認：使用者可以新增、刪除或重新排序。

**完成標準：** 每個階段都依序命名，且對每一個要擷取的數值都清楚知道 (a) 人類要從哪裡取得它，(b) 它會被寫到哪裡（`.env`、GitHub secret、兩者都要，或哪裡都不用；有些階段純粹是動作），以及 (c) 它是不是機密（要隱藏輸入）還是公開的。

### 2. 描繪每個階段的路徑

針對每個階段，寫下人類要遵循的精確路徑：要開啟哪個網址、要在那裡做什麼、數值顯示在哪裡、它會填入哪個變數：例如「儀表板 → Developers → API keys → Reveal test key → 複製」。如果你並不真正清楚目前的介面或確切的指令，就直說，並詢問使用者或查閱文件：絕不要憑空捏造可能不存在的步驟。

**完成標準：** 每個階段都對應到陌生人也能照著做的具體指示。

### 3. 撰寫精靈

把 `template.sh` 複製到目標路徑。把範例階段換成你寫的每一個步驟，各自對應一個 `stage`，依相依順序排列。使用程式庫提供的輔助函式：`stage`、`say`/`step`、`open_url`、`ask`/`ask_secret`、`write_env`、`set_secret`/`set_var`、`pause`/`confirm`。把 `TOTAL_STAGES` 設定為你所撰寫的階段數量。

維持範本設定的標準：在詢問數值之前先開啟對應網址、任何機密都要用 `ask_secret`、每一個要保存的數值都要用 `write_env`、只對 CI 真正需要的數值用 `set_secret`，並在任何不可逆的動作前用 `confirm`。每個 `stage` 都會清空畫面，只顯示目前這一步：讓每個階段只專注在一件事上，這樣人類需要的內容才不會被捲動出畫面。不要動到標記線以上的程式庫部分。

### 4. 驗證並交接

- 執行 `bash -n <script>`；如果有 `shellcheck` 就一併執行。
- `chmod +x <script>`。
- 不要自己從頭到尾跑一遍：它會開啟瀏覽器並卡在等待人類輸入。改用靜態方式追蹤它：確認第 1 步中的每一個數值都有被擷取，並落在第 1 步所說的地方，且每一個 `set_secret` 的名稱都完全對應 CI 中某個 `secrets.*` 參照。
- 告訴使用者要如何執行它。如果這是一個可重複使用的設定路徑，就把它提交進版本控制，並在 README 中連結過去，讓下一個人直接執行這個腳本，而不是再去問 AI。
