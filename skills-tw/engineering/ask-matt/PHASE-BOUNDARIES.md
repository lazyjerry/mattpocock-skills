# 階段界線（Phase Boundaries）

**階段（phase）** 是 session 中的一個工作段落：grilling、implementation、QA。這個定義是刻意模糊的：當你覺得「好，這部分做完了」時，一個階段就結束了。

**階段界線（phase boundary）** 是兩個階段之間的空隙，也是唯一該做這個決定的地方。在階段進行到一半時，其實沒有決定可做：要嘛繼續，要嘛把剩下的工作拆給 subagent。在階段中途做 compact 會讓 agent 失去脈絡。

## 五個選項

| 選項         | 作用                                                    |
| ------------ | -------------------------------------------------------- |
| **Continue** | 留在同一個 session 中，完全不切換 context。                    |
| **`/clear`** | 清空 context window，從零開始。                  |
| **`/handoff`** | 寫出一份可攜式的 markdown 檔案，讓你能在任何地方用它開新 session。 |
| **Subagent** | 把任務送到它自己的 context window，並取得回報。     |
| **`/compact`** | 壓縮目前的 context，並用摘要開一個新的 session。  |

## 決策樹

在界線處由上往下判斷。第一個 **是** 就採用。

**1. 你能繼續留在這個 session 嗎？** 有兩種情況答案是「是」：下一個階段需要這個階段作為 **主要來源（primary source）**，或者你還有足夠的 [smart zone](https://www.aihero.dev/ai-coding-dictionary/smart-zone)（約 150k tokens）能讓下一個階段順利進行。Grilling → implementation 就是標準的「是」：implementation 需要的是逐字的推理過程，而不是它的摘要。Continue 不花任何成本、也不會遺失任何東西，所以在考慮其他選項之前，先排除這個可能性。

**2. 這個 context 跟接下來要做的事無關嗎？** 這個 session 裡的一切（探索過程、決策、死路）是否都可以丟棄？如果是，就用 **`/clear`**。這是棋盤上最便宜的一步：不花時間、還能把整個視窗還給你。`/clear` 也不是不可逆的：舊的 session 仍然可以恢復。

判斷錯誤的代價是單向的。清掉一個 *相關* 的 context，你就會失去建構這些東西背後的 **原因（why）**，之後再怎麼回頭讀 diff 也找不回來。

**3. 你需要交接（hand off）嗎？** `/handoff` 適用範圍很窄。只有在以下情況你才需要它：

- 換到 **新的 harness**（Claude → Codex）、
- 移到 **新的目錄** 或 repo、
- 把工作交給 **同事**、
- 或是在 **階段中途** 分岔出一個附帶任務、又不想打斷手上正在做的事。

以上就是全部的情況。`/handoff` 提供的價值是 **可攜性（portability）**：一份能帶著走的檔案。如果沒有東西要移動，你就不需要它。

**4. 這個任務可以離開鍵盤（AFK）完成嗎？** 這個任務的範圍是否夠明確，可以在你不在場、不需要引導的情況下執行？如果是，就把它送給 **subagent**，並且不動這個 session。自動化 review 就是標準案例：agent 讀 diff 並回報結果，過程中不需要你介入。

**5. 否則就用 `/compact`。** context 相關、同一個 harness、同一個目錄，而且你需要持續參與其中：這就是決策樹最後會走到的地方，而且經常走到這裡。給它一個指示（例如 `/compact we're going to QA this area`），讓摘要保留下一個階段所需要的內容。

`/compact` 是 **預設選項，而不是第一選擇**。它排在最後，是因為前面四個問題都比它更便宜或更精確。從這裡開始的失敗模式，就是新的 session 對某個被摘要抹平的決策，抱持著錯誤的自信。

## 主要來源與次要來源

除了 **Continue** 之外，其他每個動作都會把一個 **主要來源（primary source）** 變成 **次要來源（secondary source）**：session 發生的實際過程，被換成了它的摘要。這個交換的形態永遠一樣：

| 來源                            | 資訊量 | 雜訊 | 可調整空間 |
| --------------------------------- | ----------- | ----- | ------------ |
| 主要來源（Continue）                | 完整        | 多   | 少         |
| 次要來源（`/compact`、`/handoff`） | 有損        | 較少   | 多       |

這就是為什麼問題 1 要排第一。只有在留下來的成本高於它帶來的價值時，你才需要付出「有損」這個代價。

## 這些都是主觀判斷

這些問題並不是客觀的：每一題都帶有品味成分，同樣的界線在不同天可能會走向不同的方向。它的價值在於 **依序** 提問，並且是在界線處提問，而不是在工作進行到一半時提問。
