# 學習記錄格式

學習記錄存放於 `./learning-records/`，並採用連續編號：`0001-slug.md`、`0002-slug.md`，依此類推。目錄採懶惰建立方式：只有在第一筆記錄寫入時才建立。

它們是教學版本的 ADR：用來記錄非顯而易見的教訓、關鍵洞見，以及已表明的先備知識，作為未來工作階段的指引依據。這些記錄會用來計算最近發展區（zone of proximal development）。

## 範本

```md
# {所學到或所確立內容的簡短標題}

{1 到 3 句話：說明學到了什麼（或確立了哪些先備知識），以及這對未來工作階段的教學安排有何影響。}
```

這就是完整的格式。一筆學習記錄可以只是一個段落。其價值在於記錄「這件事現在已經確認為已知」以及「這為何改變接下來該教的內容」，而不在於把各段落填滿。

## 選用區塊

只有在確實能帶來價值時才加入以下區塊。大多數記錄並不需要。

- **狀態** frontmatter（`有效 | 已由 LR-NNNN 取代`）：當先前的理解事後證實有誤並被取代時，這個欄位就派得上用場。
- **證據**：使用者如何展現出理解（回答了某個問題、完成了某項練習、提及過往經驗）。當該主張日後可能會被重新檢視時，這一項很有用。
- **影響**：這項理解為未來工作階段開啟或排除了哪些可能性。當這並非顯而易見時，值得記錄下來。

## 編號方式

掃描 `./learning-records/`，找出目前最大的編號，並加一遞增。

## 何時該撰寫學習記錄

符合以下任一情況時，就應撰寫一筆記錄：

1. **使用者展現出對某個非瑣碎主題的真正理解**：不只是接觸過而已，而是有證據顯示他們能正確運用該概念。這會為接下來該教的內容設下新的門檻。
2. **使用者揭露了先備知識**：例如「我已經知道 X 了。」把這件事記錄下來，讓未來的工作階段不會重複教學。同時也要記錄使用者所聲稱的理解深度。
3. **某個迷思概念被糾正**：使用者原本相信某個錯誤的觀念，現在已經明白為何錯誤。這類記錄價值很高：它們能預測相關主題未來可能出現的卡關點。
4. **任務目標因學習而轉向**：使用者發現自己真正在意的其實跟原本想的不一樣。請與 [[MISSION.md]] 交叉連結，並更新它。

### 哪些情況不適用

- 只是被講到、被涵蓋過的內容。涵蓋到不等於學會了。要等到有證據出現。
- 已經在 [[GLOSSARY.md]] 中以術語定義簡要記錄過的內容。不要重複記錄。
- 逐次工作階段的活動紀錄。學習記錄不是流水帳日誌：它們是具有決策價值的洞見。

## 取代機制（Supersession）

當一筆較新的記錄與較舊的記錄相牴觸時（使用者的理解變得更深入或被修正），應將舊記錄標記為 `狀態：已由 LR-NNNN 取代`，而不是直接刪除。理解演變的歷程本身就是有用的訊號。
