# MISSION.md 格式

`MISSION.md` 放在工作區的根目錄。它記錄了使用者學習這個主題的_原因_。每一個教學決策（接下來要教什麼、要呈現哪些資源、要設計哪些練習）都應該能追溯到這份文件。

## 範本

```md
# 任務目標：{主題}

## 為什麼
{1-3 句話。使用者追求的具體現實目標。當他們具備這項技能後，生活或工作中會有什麼改變？避免使用「為了理解 X」這類抽象的說法，要挖掘出背後真正的成果。}

## 成功的樣子
- {使用者將能做到的具體、可觀察的事}
- {另一件具體的事}
- {…}

## 限制
- {時間、預算、既有承諾、學習偏好，任何會限制做法的因素}

## 範圍之外
- {使用者目前明確不想追求的相關主題，保護最近發展區}
```

## 規則

- **一個工作區一個任務目標。** 如果使用者想學兩個不相關的東西，那就是兩個工作區。
- **具體優於抽象。**「十月前跑完一場半馬」勝過「變得更健康」。「把 Rust CLI 交付給我的團隊」勝過「學習 Rust」。
- **對模糊不清的說法要提出質疑。** 如果使用者說不出「為什麼」，就先訪談他們，再動筆寫任何東西。一份糟糕的任務目標比沒有任務目標更糟。
- **當現實改變時要修訂。** 任務目標會變動。當使用者的目標改變時，更新這份檔案：不要留著過時的任務目標去引導未來的工作階段。
- **保持簡短。** 如果 `MISSION.md` 超過一個畫面的長度，它就不再是指南針，而變成了計畫書。
