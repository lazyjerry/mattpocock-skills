# 技能運作機制

[`writing-for-agents`](SKILL.md) 中專屬於技能的分支：當文件本身是一個技能時，有哪些地方會不同（frontmatter、呼叫方式的選擇，以及路由型技能）。除此之外，關於撰寫技能的一切都是 `SKILL.md` 中的通用參考資料。

## 呼叫方式

有兩種選擇，各自在兩種負載之間做取捨：

- **模型觸發**的技能會保留 `description`，讓 agent 能自主觸發它，其他技能也能連結到它。你仍然可以手動輸入它的名稱：模型觸發一定**包含**使用者的觸及範圍；description 只會增加 agent 的可發現性，絕不會削減人類的可及性。description 是這個技能最上層的情境指標，被強制常駐載入：用永久的情境負載換取可發現性。一個內容全屬參考資料的、模型觸發的技能，也可以作為共用參考資料的歸屬地：因為其他技能可以呼叫它，多個技能所需的參考資料就能集中存放在同一處。運作方式：省略 `disable-model-invocation`，並撰寫一段面向模型的 description，涵蓋各種觸發分支（`SKILL.md` 中的指標撰寫規則全部適用）。
- **使用者觸發**的技能會把 description 從 agent 的觸及範圍中移除：只有親自輸入其名稱的人類才能呼叫它，其他技能也無法呼叫它。情境負載為零，但要付出認知負載：你自己就是必須記得這個技能存在的索引。運作方式：設定 `disable-model-invocation: true`；`description` 會變成面向使用者的內容：一行摘要，並去除觸發清單。

只有在 agent 必須能自行連結到這個技能，或其他技能必須連結到它時，才選擇模型觸發。如果它只會被手動觸發，就設為使用者觸發，不用付出情境負載。

兩個使用者觸發的技能都需要的共用參考資料，無法放在其中任何一個裡面：因為兩者都沒有 description，彼此都無法呼叫對方。應將它移到技能系統之外的一般檔案：任何技能都能指向的外部參考資料。

## 依呼叫方式拆分

拆分的呼叫方式面向（拆分的順序面向則在 `SKILL.md` 中）：當你有一個明確的前導詞、應該能單獨觸發某個技能時（一個你實際會在提示詞中使用的觸發詞），或是另一個技能必須連結到它時，就該把它拆成一個模型觸發的技能。你要為這個新增的、常駐載入的 description 付出情境負載，所以這種獨立的可及性必須值得。

## 路由型技能

當使用者觸發的技能數量多到超出你能記住的範圍時，這種累積起來的認知負載可以透過**路由型技能**來解決：一個使用者觸發的技能，列出所有其他技能以及各自適用的時機，讓人類只需要記住一個技能，而不是一大堆。它只能提示，不能觸發它們：因為使用者觸發的技能沒有 description，除了人類之外沒有任何東西能連結到它們。
